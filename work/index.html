    Zerg and ZTC

    Zerg is a spec-driven framework for autonomous coding agents, and ZTC is its terminal client. My work includes parallel tool dispatch so agents stop queueing behind each other, background sub-agents for work that outlives a single turn, worktree-isolated batch execution so concurrent writers do not collide, a sandboxed multi-agent workflow runtime, MCP and provider routing, and the live web interface. People can watch a run as it happens.

    Epoch AI / Zerg AI · ZTC: TypeScript on Node, Rust native packages, React browser mirror · Zerg: Python core, Vue web IDE

    Forward-deployed engineering

    I work with two customers whose names are private. For an organization-management and resource-planning platform, I built continual-validation harnesses that score agent output against deterministic checks of state, tools, artifacts, browser behavior and visual output. These checks catch regressions before changes are accepted. The other is an AI procurement intake and approval portal with grounded vendor research, approvals that stay owned by a human, and RBAC with separation-of-duties controls.

    Epoch AI / Zerg AI · customer names withheld, no public artifact

  • 2023 to 2025

    MOBIVOLT

    For this $5M+ DOD-funded fuel-cell program, I built the desktop apps that run the automated test stands, in C# on .NET with Avalonia. I wrote a Python and PyQt hardware-in-the-loop simulator with a serial firmware bridge, injecting sensor values every 100ms and polling at 200ms against plant models. Firmware could then be exercised without a rig. I ported PIC32MZ firmware onto Harmony v3 across 50+ application and driver modules with 2,500+ lines of C tests, and kept 5 automated test stands processing 100+ concurrent data streams with zero downtime across 18 months. I also handled migrations and did circuit work in KiCad and ngspice.

    C#, .NET, Avalonia, Python, PyQt, C, PIC32MZ, Harmony v3, KiCad, ngspice · defense program, no public artifact

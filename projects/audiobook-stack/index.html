My audiobook setup

I built Epub Listener, Hark and Kestrel to turn books into audio and listen on my device.

Kestrel's measurements, and the mlx-audio fix I found while building it, are in ML & Research.

I read web novels and light novels. Many run to hundreds of chapters, and I often wait for translations. I wanted to listen while walking.

I wrote a CLI that turns an EPUB into a narrated MP3 with chapter markers. That became Epub Listener. The audio files were large and difficult to move between devices, so I built Hark to hold them, which parses the MP3 in the browser and keeps the audio on the device. The server receives only titles, chapters, my position and my playback history.

Generating audio for a 600-chapter book still took hours. I distilled the vocoder to speed it up. That became Kestrel, with measurements in the table on its project page. Generation is faster now, though the audio still sounds slightly worse than the original model.

I used the word timings from Epub Listener to add read-along in Hark. The player highlights the narrated sentence, marks the word being spoken, and jumps if you tap somewhere else. Playback and read-along work in airplane mode.

In August, I integrated the generation step into Hark. Kestrel now runs inside Hark, so the browser takes a PDF or an EPUB and narrates it on the device. This path no longer needs the CLI or my laptop.

  • Epub Listener github

    Python CLI. EPUB in, chaptered MP3 out, via Edge-TTS, local Kokoro, Kestrel on Apple Silicon, any Hugging Face text-to-speech pipeline model, or any local command that writes audio. Checksum-based resume so a failed run does not start over. Embeds a timestamped read-along transcript, median word-onset error under 30ms.

  • Kestrel github

    My speech-generation engine. Its speed measurements, quality limits and independent audit are on the Kestrel project page.

  • Hark live (sign-in)

    Installable offline-first audiobook PWA. Import a chaptered MP3, or a PDF, EPUB, DOCX, text, Markdown or HTML file it narrates on the device with Kestrel through WebGPU, WASM where there is none. Everything is parsed and stored on-device, server sees metadata only. Karaoke-style read-along with sentence highlight and word-level marking. Playback and read-along work offline; only the first narration downloads the model, about 39MB of weights and a 24MB runtime.

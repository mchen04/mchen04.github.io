Books, and the audio stack they caused

Where Kestrel, Epub Listener and Hark came from. It starts with wanting to listen to a web novel on a walk and ends with me distilling a vocoder, which is a ridiculous way to solve that problem.

I read a lot of web novels and light novels. The good ones run to hundreds of chapters and the translation pace means you are always waiting, so at some point I wanted to listen to them instead of reading them, mostly so I could do it while walking somewhere.

Nothing would do it. So I wrote a CLI that takes an EPUB and gives back a narrated MP3 with real chapter markers, which is Epub Listener. The files turned out too big and too awkward to move around, so I built Hark to hold them, which parses the MP3 in the browser and keeps the audio on the device. The server only ever sees titles, chapters, my position and my playback history.

A 600-chapter book was still hours of waiting. That is when I went and distilled the vocoder. That is Kestrel, the same project as the benchmark table on its own page. It's fast enough now that the pipeline stopped being the thing I waited on. It also still sounds slightly worse than the model it came from, which is the part I did not manage to fix.

Hark got a read-along mode out of it, because Epub Listener already knew the word timings the TTS engine produced and it seemed wasteful to throw them away. The player highlights the narrated sentence, marks the word being spoken, and jumps if you tap somewhere else. It works on a plane, in airplane mode.

In August the loop closed on itself. Kestrel now runs inside Hark, so the browser takes a PDF or an EPUB and narrates it on the device. The CLI is no longer in the path, and neither is my laptop.

  • Epub Listener github ↗

    Python CLI. EPUB in, chaptered MP3 out, via Edge-TTS, local Kokoro, Kestrel on Apple Silicon, any Hugging Face text-to-speech pipeline model, or any local command that writes audio. Checksum-based resume so a failed run does not start over. Embeds a timestamped read-along transcript, median word-onset error under 30ms.

  • Kestrel github ↗

    The reason the pipeline is fast enough to use, and the one that fails its own quality battery. The numbers and the audit are under Measured.

  • Hark live ↗ (sign-in)

    Installable offline-first audiobook PWA. Import a chaptered MP3, or a PDF, EPUB, DOCX, text, Markdown or HTML file it narrates on the device with Kestrel through WebGPU, WASM where there is none. Everything is parsed and stored on-device, server sees metadata only. Karaoke-style read-along with sentence highlight and word-level marking. Playback and read-along work offline; only the first narration downloads the model, about 39MB of weights and a 24MB runtime.
